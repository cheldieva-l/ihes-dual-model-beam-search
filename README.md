# IHES Dual-Model Beam Search

This repository contains a clean-room, replay-verified implementation of MLP-guided beam search for the 72-point puzzle in the [CayleyPy IHES Cube competition](https://www.kaggle.com/competitions/cayleypy-ihes-cube). It provides three English-language Kaggle notebooks:

1. a single-model global beam search;
2. symmetry and reverse (NISS-style) searches with exact path conversion;
3. a bidirectional symmetry/reverse search with paired-projection contrast scoring, complete reverse-frontier mapping, blind intersection, and an auditable known-path retention diagnostic.

The default controlled case is puzzle `106`, model `1778521793`, and beam width `1,000,000`. The known 24-move reference path is used only by the third notebook's optional diagnostic. Ordinary searches do not receive a known midpoint, midpoint hash, or protected path.

## Safety and reproducibility

- Every accepted path is replayed from the original, unrotated state with the official 18 generators.
- Submission validation replays all 1,003 rows, not only the replaced row.
- No generator is globally excluded. Immediate-inverse pruning exists as an explicit option and is disabled in the published configurations.
- Diagnostic last-slot protection is disabled by default. When enabled, it can retain a known state only after exact comparison proves that the state was generated by the current beam.
- The bidirectional blind run ranks every candidate with `primary MLP score - paired-projection MLP score`; protected diagnostic frontiers are never passed to its intersector.
- The code reports where a known path is naturally retained, where it first drops out of true top-K, and where a diagnostic run protects it. This is an experiment-specific invariant, not a guarantee for all 1,003 puzzles.
- Model weights, competition data, private datasets, credentials, tokens, and generated frontier files are not committed. Kaggle assets are discovered at runtime.

## Model identity

Every run directory and log contains a canonical model identifier. The controlled run uses `1778521793`, resolving to `model_p888-t000_1778521793.json` and `p888-t000_1778521793_e32692.pth`. The registry also records the two Kaggle assets carrying model `1780290207` and resolves the `ihes-e08192` Kaggle Model alias to canonical model ID `1763232740`. The alternate `1780290207-ihes` asset is recognized as 11 Apple Archive shards; raw concatenation is explicitly rejected, and the direct epoch-40960 dataset is preferred for portable Kaggle runs. Assets are referenced, not redistributed.

## Results

The completed remote outputs were inspected on 2026-08-28. Both finished runs used puzzle `106`, model `1778521793` at epoch `32692`, beam width `1,000,000`, and all 18 official generators.

| Notebook | Runtime | Validated symmetries | Direction selected | Solution length | Exact replay | `submission.csv` |
|---|---:|---:|---|---:|---|---|
| Base MLP | 39m 42s | n/a | direct | 24 | passed | present; 1,003 rows validated |
| Symmetry + reverse | 2h 41m 1s | 48 | direct, identity frame | 24 | passed | present; 1,003 rows validated |
| Bidirectional symmetry + reverse | v1: 48m 20s; v2: 2h 15m 57s; v3: 1h 51m 44s; all error | identity | v1-v3: no exact meeting | pending | pending | pending |

The two completed solution runs found the same 24-move path. The symmetry/reverse run therefore verifies the transformation and replay pipeline but does not improve the controlled case. Bidirectional versions 1 through 3 correctly rejected empty blind exact intersections instead of manufacturing a protected result. Versions 2 and 3 mapped all five one-million-row reverse frontiers before hashing and passed all 25 known-path mapping checks. Their ordinary rankings naturally dropped the known forward point at depth 8 and the reverse point at depth 6. The separate protected diagnostics proved exact generation before every forced last-slot retention through depth 16; those protected frontiers were not used by the blind join. Version 4 preserves the exact intersection as the first mandatory stage and then, only if it is empty, blindly scans all 18 generated one-move children of each complete frontier against the opposite complete frontier. Shell children are explicitly not reported as top-K. Results are recorded only after a completed remote run. No unexecuted notebook is presented as evidence of a solution, and no cross-puzzle path-retention guarantee is claimed.
